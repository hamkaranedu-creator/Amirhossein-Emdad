# دستیار هوشمند مدیریت تقویم (n8n + تلگرام + Google Calendar)

فایل ورکفلو: [`calendar-assistant-workflow.json`](calendar-assistant-workflow.json)

ربات تلگرامی که پیام متنی یا صوتی فارسی و انگلیسی را می‌گیرد و رویدادهای Google Calendar را می‌سازد، نشان می‌دهد، ویرایش و حذف می‌کند. ویرایش و حذف فقط پس از تأیید صریح کاربر انجام می‌شود. تاریخ‌ها به وقت تهران محاسبه می‌شوند و در پاسخ‌ها به شمسی نمایش داده می‌شوند.

## مسیر کار ورکفلو

```
Telegram Trigger → Authorized user? ─┬─ نه → Ignore unauthorized
                                     └─ بله → Voice message?
        ├─ صوتی → Get voice file → Transcribe a recording → Prepare text (voice) ─┐
        └─ غیرصوتی → Text message? ─┬─ متن → Prepare text (typed) ───────────────┤
                                    └─ سایر → Send unsupported input message      │
                                                                                  ▼
          Calendar Agent (GPT-4o + حافظه ۱۰ پیام + ۴ ابزار تقویم) ─┬─ Send reply
                                                                    └─ خطا → Send error message
```

خطای دریافت فایل صوتی، تبدیل صوت به متن یا خطای عامل هوشمند به پیام «خطایی رخ داد» در تلگرام ختم می‌شود.

## راه‌اندازی

1. **Import:** در n8n از منوی Workflows گزینهٔ Import from File را بزنید و فایل JSON را انتخاب کنید.
2. **Credentialها:** شناسهٔ Credentialهای داخل فایل مربوط به نمونهٔ قبلی n8n است. روی هر نود زیر کلیک کنید و Credential خودتان را انتخاب کنید:
   - **Telegram API** (توکن ربات از BotFather): Telegram Trigger، Get voice file، Send reply، Send error message، Send unsupported input message
   - **OpenAI API**: GPT-4o model، Transcribe a recording
   - **Google Calendar OAuth2**: Create event، List events، Update event، Delete event
3. **Chat ID مجاز:** نود `Authorized user?` مقدار `$vars.ALLOWED_CHAT_ID` را می‌خواند.
   - **Variables فقط در پلن‌های پولی n8n (Pro/Enterprise و برخی پلن‌های Cloud) وجود دارد.** در نسخهٔ رایگان Community این مقدار خالی است و ربات **همهٔ پیام‌ها را بی‌صدا نادیده می‌گیرد.**
   - اگر Variables دارید: در Settings → Variables متغیری با نام `ALLOWED_CHAT_ID` بسازید.
   - اگر ندارید: در نود `Authorized user?` مقدار سمت راست شرط را مستقیماً به Chat ID خودتان تغییر دهید، مثلاً `123456789`.
   - برای پیدا کردن Chat ID یک بار ورکفلو را تست کنید و در خروجی Telegram Trigger مقدار `message.chat.id` را ببینید.
4. **تقویم:** همهٔ ابزارها روی تقویم `primary` حساب گوگلِ متصل کار می‌کنند.
5. **فعال‌سازی:** ورکفلو را Active کنید. Telegram Trigger وبهوک را خودش ثبت می‌کند، پس آدرس n8n باید HTTPS و از اینترنت در دسترس باشد (`WEBHOOK_URL` درست تنظیم شده باشد).

## چه چیزهایی بیرون از n8n بررسی شد

- **ساختار JSON:** فایل معتبر است. ۲۳ نود دارد که ۴ تای آن یادداشت است. همهٔ اتصال‌ها به نودهای موجود اشاره می‌کنند و هیچ نود عملیاتی بی‌اتصال نمانده است.
- **عبارت تاریخ شمسی (Luxon):** عبارت داخل دستور سیستمی با Luxon 3 و Node 22 اجرا شد. نمونه‌ها:
  - ۲۰۲۶-۱۱-۲۵ = چهارشنبه ۴ آذر ۱۴۰۵
  - ۲۰۲۶-۱۰-۱۷ = شنبه ۲۵ مهر ۱۴۰۵
  - ۲۰۲۶-۰۳-۲۱ = ۱ فروردین ۱۴۰۵
  - ۲۰۲۵-۰۳-۲۰ = ۳۰ اسفند ۱۴۰۳ (سال کبیسه)
  - ساعت ۰۰:۳۰ بامداد تهران که در UTC هنوز روز قبل است، درست روز تهران را نشان می‌دهد.
  - جدول ۶۷ روزه (از یک هفته قبل تا دو ماه بعد) درست ساخته می‌شود.
- **شرط لازم برای تاریخ شمسی:** Node باید با ICU کامل اجرا شود. ایمیج‌های رسمی n8n این را دارند. اگر در خروجی، تاریخ به‌جای شمسی میلادی بود، نسخهٔ Node شما ICU کامل ندارد.

## چه چیزهایی فقط داخل n8n واقعی قابل تأیید است

- Import بدون هشدار و شناخته‌شدن نسخهٔ نودها (typeVersion)، به‌خصوص `Transcribe a recording` (نسخهٔ 2.3) و `GPT-4o model` (نسخهٔ 1.2) در نسخهٔ n8n شما.
- Credential مدل‌های OpenAI در فایل با علامت `__aiGatewayManaged` ذخیره شده است. پس از Import حتماً Credential را دستی انتخاب کنید.
- رفتار واقعی GPT-4o در سناریوهای بالا، به‌خصوص تأیید پیش از ویرایش و حذف و تبدیل تاریخ‌های شمسی خارج از جدول.
- ثبت وبهوک تلگرام و دسترسی OAuth گوگل.
- اگر پاسخ مدل نویسه‌هایی مثل `<` داشته باشد و نود Telegram آن را با parse mode پیش‌فرض بفرستد، ارسال ممکن است خطا بدهد. `Send reply` روی «ادامه در صورت خطا» تنظیم شده است، پس در این حالت کاربر هیچ پاسخی نمی‌گیرد. اگر این اتفاق افتاد، در Additional Fields نود `Send reply` گزینهٔ Parse Mode را روی متن ساده بگذارید.

## تغییرات این نسخه

- **دستور سیستمی:** حافظهٔ عامل فقط متن گفت‌وگو را نگه می‌دارد و شناسهٔ رویداد (event_id) از نتیجهٔ ابزار در آن نمی‌ماند. حالا دستور سیستمی صریحاً می‌گوید بعد از «بله»ی کاربر، رویداد دوباره با List events پیدا شود و بعد ویرایش یا حذف انجام شود.
- **کلید حافظه:** `sessionKey` با `String()` به متن تبدیل می‌شود تا کلید جلسه همیشه متنی باشد.
